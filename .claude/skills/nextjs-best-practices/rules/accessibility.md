# アクセシビリティ

## 役割のある要素を使う

- 押して何かが起きるものは `<button>`、移動するものは `<a>`（`<Link>`）にする。`<div onClick>` にしない
- 見出しは `h1` から順に階層を守る。見た目の大きさのために見出しの階層を飛ばさない
- 一覧は `<ul>`・`<ol>`、表は `<table>` にする

## 名前を付ける

- 入力には必ずラベルを付ける。placeholder をラベルの代わりにしない
- 文字のないボタン（アイコンだけ）には `aria-label` を付ける
- 画像には `alt` を付ける。飾りの画像は `alt=""` にする

## 状態を伝える

- 押せないボタンは `disabled` にする。見た目だけ薄くしない
- 開閉する部品は `aria-expanded` で状態を示す。shadcn/ui（Radix UI）の部品は自動で付くので、自作しない
- 入力の誤りは `aria-invalid` と、近くの文言で示す

## キーボード

- すべての操作をキーボードだけでできるようにする
- ダイアログを開いたらフォーカスを中へ移し、閉じたら元へ戻す。Radix UI の部品を使えば満たされる
- フォーカスの枠を消さない

ここで付けた役割とラベルは、テストで要素を探す手がかりにもなる。`getByRole` で探せない部品は、利用者の支援技術からも見つけにくい。
