# 非同期の状態（Async React）

待つこと・失敗すること・前の表示を残して更新することを、部品の中の分岐ではなく React の仕組みに任せる。この考え方を Async React と呼ぶ。

| 状態                       | 任せる先                                                             |
| -------------------------- | -------------------------------------------------------------------- |
| 読み込み中                 | Suspense                                                             |
| 取得の失敗                 | ErrorBoundary                                                        |
| 取り直している間           | transition（`startTransition`・`useTransition`・`useDeferredValue`） |
| 送信中                     | Actions（`useTransition` の `isPending`・`useActionState`）          |
| 成功を待たずに表示を変える | `useOptimistic`                                                      |

## 3つの状態を必ず決める

データを表示する部品は、読み込み中・取得の失敗・0件の3つの表示を必ず持つ。どれかが欠けると、利用者は空白の画面を見て、壊れたのか待てばよいのか分からない。

| 状態       | 表示の目安                                     |
| ---------- | ---------------------------------------------- |
| 読み込み中 | 最終的な形に近いスケルトン                     |
| 取得の失敗 | 何が失敗したかと、利用者にできること（再試行） |
| 0件        | 0件であることと、次にできること                |

読み込み中と取得の失敗は境界が受け持つ。0件だけは部品が受け持つ。

## Suspense と ErrorBoundary

- データを取る部品は、データがある前提で書く。SWR は `suspense: true` で呼び、`isLoading`・`error` で分岐しない
- ErrorBoundary は Suspense の外側に置く。取得の失敗は Suspense の中で投げられる
- 境界は、失敗しても残りの画面が使える単位で置く。ページ全体を1つで囲まない。逆に、細かく置きすぎて代替表示が画面中に点在しないようにする
- ErrorBoundary の代替表示には再試行の手段を置く（`resetErrorBoundary`）
- Suspense の代替表示は、置き換わったときに画面が大きく跳ねない大きさにする

## transition

- 条件を変えて取り直すと、部品がもう一度 suspend して代替表示へ戻る。検索の条件・タブ・ページ送りの更新は `startTransition` で包み、前の結果を残したまま取り直す
- 入力に合わせて絞り込むときは、入力の値はすぐ更新し、取得に使う値を `useDeferredValue` で遅らせる
- 取り直していることは `isPending` で示す（前の結果を薄くするなど）。代替表示に戻さない

## 送信

- 送信中の状態を `useState` で持たず、`useTransition` の `isPending` で表す。フォームは `useActionState` を使ってよい
- 成功を待たずに表示を変えたいときは `useOptimistic` を使う。失敗すれば元の表示に戻る
- 送信の失敗は ErrorBoundary に投げない。操作した場所の近くに出す
- 成功したときに何が変わったかが画面で分かるようにする。黙って成功させない

## 合わない場面

Suspense は「データがそろうまで表示しない」仕組みである。次のような場面では合わないことがある。プロジェクトの規約に扱いが書かれていればそれに従い、なければ分岐で書く前に確認する。

- 取得の結果によって別の画面へ移す判定（ログイン中の利用者の確認など）
- 取得するかどうかが操作で決まり、取得しない間にも表示が要るとき
