# 非同期の状態

## 3つの状態を必ず決める

データを表示する部品は、読み込み中・取得の失敗・0件の3つの表示を必ず持つ。どれかが欠けると、利用者は空白の画面を見て、壊れたのか待てばよいのか分からない。

| 状態       | 表示の目安                                         |
| ---------- | -------------------------------------------------- |
| 読み込み中 | 最終的な形に近いスケルトン、または短い文言         |
| 取得の失敗 | 何が失敗したかと、利用者にできること（再読み込み） |
| 0件        | 0件であることと、次にできること                    |

## 書き方は2つある

| 書き方                                                                    | 向いている場面                           |
| ------------------------------------------------------------------------- | ---------------------------------------- |
| フックを `suspense: true` で呼び、上位で Suspense と ErrorBoundary で囲む | 画面の大きな区画をまとめて待つとき       |
| フックの `isLoading` と `error` で分岐する                                | 部品の中で状態ごとに細かく出し分けるとき |

同じ画面の中ではどちらかに揃える。混ぜると、同じ失敗が場所によって違う形で出る。

## Suspense と ErrorBoundary

- ErrorBoundary は Suspense の外側に置く。取得の失敗は Suspense の中で投げられる
- 境界は、失敗しても残りの画面が使える単位で置く。ページ全体を1つで囲まない
- ErrorBoundary の代替表示には再試行の手段を置く（`resetErrorBoundary`）
- Suspense の代替表示は、置き換わったときに画面が大きく跳ねない大きさにする

## 送信の状態

- 送信中は、送信のボタンを押せなくし、処理中であることを文言で示す
- 送信の失敗は、利用者が操作した場所の近くに出す
- 成功したときに何が変わったかが画面で分かるようにする。黙って成功させない
