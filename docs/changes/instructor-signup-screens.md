# 講師の新規登録（仮登録・認証コード入力）の画面を作る

## 目的

講師が自分で新規登録できるように、仮登録の画面と、認証コードを入力して本登録する画面を用意する。今回は画面だけを作り、API にはつながない。

## 背景

JKA-1820。講師本人による登録は、バックエンドの仕様で認められている。講師自身が手続きを始めた場合は、どのマネージャーの配下にも登録しない（AC-ACCOUNT-018・BR-SHARED-018）。認証不要の仮登録・本登録の API もあるが、つなぐのは続きの Issue で行う。

次の点はチケットで要確認とされており、この変更では決めない。

- 仮登録の画面への入口をどこに置くか
- 認証メールに書かれる URL は受講生と講師で共通（`/verification/{token}`）で、講師用の画面に届かない。API をつなぐ Issue の前提になる

## 変更する振る舞い

| 対象                         | 現在       | 変更後                                                                                                                                                                                   |
| ---------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 仮登録の画面（新設）         | 画面がない | 講師名・姓・名・メールアドレスを入力して登録できる。入力が検証を通らなければ、理由を入力欄の下に出す。登録を押すと、入力したメールアドレスに認証コードを送った旨の案内を同じ画面に出す |
| 認証コード入力の画面（新設） | 画面がない | 案内文を出し、認証コード・パスワード・パスワード再入力を入力して登録できる。入力が検証を通らなければ、理由を入力欄の下に出す                                                             |
| 認証コードの扱い             | —          | 英大文字・英小文字・数字が混ざった4文字として、入力のまま受け付ける。数字だけに絞らず、大文字にも小文字にも変えない                                                                     |
| URL の token                 | —          | 認証コード入力の画面に表示しない                                                                                                                                                         |
| 送信の失敗の表示             | —          | どちらの画面も、フォームの上に送信の失敗を出す場所を用意する。中身は API 連携の Issue で入れる                                                                                           |
| 前提にする API の振る舞い    | —          | AC-ACCOUNT-002（講師の仮登録の項目）・AC-ACCOUNT-010（本登録で受け取る値）・AC-ACCOUNT-011（パスワードの条件）                                                                          |

画面の受け入れ基準の ID は、実装の段で `AC-ISIGNUP-NNN` として新しく振る。

## 変更する範囲

| 範囲               | 内容                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------- |
| 画面               | 仮登録の画面と認証コード入力の画面。未ログインで開ける場所に置く。画面の URL を定義に足す |
| データの取得と送信 | なし。登録を押したら入力値を記録に出すだけにする                                             |
| 入力の検証         | 2つの画面の入力ルール。バックエンドの入力ルールに合わせる                                    |
| 共通の部品         | なし。既存の部品だけを使う                                                                   |

## 前提にする API

- 講師の仮登録 `POST /v1/instructors`（認証不要）。バックエンドにある
- 認証コードの検証と本登録 `POST /v1/instructors/verification/{token}`（認証不要）。バックエンドにある

どちらも今回は呼ばない。
