# 規約の検査手段

`coding-standards.md` と `documentation-rules.md` に定めた規約を、どこまで機械で判定できるかを整理する。区分の考え方はバックエンドの `docs/architecture/convention-checks.md` と同じである。

## 判定の区分

| 区分 | 意味                                 | 扱い                                         |
| ---- | ------------------------------------ | -------------------------------------------- |
| A    | 機械で判定でき、既存の違反が 0 件    | 直ちに検査に載せ、違反があれば落とす         |
| B    | 機械で判定できるが、既存に違反がある | 基準線を記録し、そこから増えた分だけを落とす |
| C    | 機械で検出できるが誤検知が混ざる     | 警告として出し、落とさない                   |
| D    | 機械で判定できない                   | レビューの観点として残す                     |

現時点で区分 B と C の規約はない。

## 検査手段の割り当て

| 手段                            | 受け持つ範囲                              | 実行する場所                             |
| ------------------------------- | ----------------------------------------- | ---------------------------------------- |
| Prettier                        | 整形                                      | 編集直後・継続的インテグレーション       |
| ESLint（`eslint.config.mjs`）   | import の向きなど、構文から判定できる規約 | 編集直後・評価・継続的インテグレーション |
| `tsc --noEmit`                  | 型の誤り                                  | 評価・継続的インテグレーション           |
| `scripts/check-conventions.mjs` | テストの書き方とドキュメント              | 編集直後・評価・継続的インテグレーション |
| Vitest                          | 画面の振る舞い                            | 評価・継続的インテグレーション           |
| 人間                            | 設計・命名・責務の妥当性                  | レビュー                                 |

編集直後の検査は `.claude/settings.json` のフックが行う。`.ts`・`.tsx` を書いた直後に整形・ESLint・検査スクリプトを、`.md` を書いた直後に整形と検査スクリプトを走らせ、違反があればその場で書き手に返す。

継続的インテグレーションは `.github/workflows/ci.yml` で、`feature/update-next-version` へ向けた PR にだけ走る。整形・ESLint・取り込む前の規約の検査・型検査・全テストを通さないと落ちる。フックは手元で気づくため、継続的インテグレーションは取りこぼしを止めるためにある。

継続的インテグレーションの環境にはバックエンドの `docs/` がないため、バックエンドの ID の実在（CHK-TEST-04・CHK-DOC-04 の一部と CHK-DOC-05）は判定されない。これらは手元の評価の段で見る。

検査には見る時機が 2 つある。起票の残骸（CHK-DOC-06）は取り込む前にだけ見る。起票は着手から実装完了まで存在しているのが正しい状態だからである。

```bash
scripts/run pnpm check-conventions        # 作業中
scripts/run pnpm check-conventions-merge  # 取り込む前
```

検査を足したときは、違反を仕込んで実際に落ちることを確かめる。鳴らない検査は、無いより悪い。

## 対応表

既存の違反数は 2026-09-28 時点の実測である。

### 部品の構成

| ID            | 規約                                                                        | 区分 | 判定手段 | 既存の違反 |
| ------------- | --------------------------------------------------------------------------- | ---- | -------- | ---------- |
| CHK-IMPORT-01 | `features/` から `components/ui/` を直接参照しない                          | A    | ESLint   | 0 件       |
| CHK-UI-01     | Presentational でデータの取得と送信をしない（SWR・axios・ドメインのフック） | A    | ESLint   | 0 件       |
| CHK-UI-02     | Presentational に業務の判定を置かない                                       | D    | レビュー | —          |
| CHK-IMPORT-02 | 別のドメインの `features/` を参照しない                                     | D    | レビュー | —          |

CHK-UI-01 は型の参照を許す。Container が受け取るコールバックの型をフックの側で定義している箇所があるためである。

CHK-IMPORT-02 は、共通へ移すべきかの判断を伴うため機械では落とさない。

### データの取得と送信

| ID          | 規約                                          | 区分 | 判定手段 | 既存の違反 |
| ----------- | --------------------------------------------- | ---- | -------- | ---------- |
| CHK-DATA-01 | 送信のフックは結果を値で返し、例外を投げない  | D    | レビュー | —          |
| CHK-DATA-02 | 読み込み中・取得の失敗・0件の表示を決めている | D    | レビュー | —          |

### テスト

| ID          | 規約                                    | 区分 | 判定手段       | 既存の違反 |
| ----------- | --------------------------------------- | ---- | -------------- | ---------- |
| CHK-TEST-02 | `Arrange`・`Act`・`Assert` を書く       | A    | 検査スクリプト | 0 件       |
| CHK-TEST-03 | `describe` と `it` の名前を日本語で書く | A    | 検査スクリプト | 0 件       |
| CHK-TEST-04 | 参照する受け入れ基準が実在する          | A    | 検査スクリプト | 0 件       |
| CHK-TEST-05 | 見た目や通信を確かめていない            | D    | レビュー       | —          |
| CHK-TEST-06 | 要素を利用者に見えるもので探す          | D    | レビュー       | —          |

CHK-TEST-01 は欠番である。バックエンドの番号と揃えるため空けている（置き場の判定は区分 C 相当で、載せる価値が小さい）。

CHK-TEST-03 は日本語であるかまでしか判定できない。利用者の視点になっているかはレビューで見る。

CHK-TEST-04 は、バックエンドの機能の略称を持つ ID（`AC-ENROLL-NNN` など）を、バックエンドの `docs/` が手元にあるときだけ判定する。リポジトリを単体で取得した環境では飛ばす。

### ドキュメント

| ID         | 規約                           | 区分 | 判定手段                         | 既存の違反 |
| ---------- | ------------------------------ | ---- | -------------------------------- | ---------- |
| CHK-DOC-04 | 存在しない ID を参照しない     | A    | 検査スクリプト                   | 0 件       |
| CHK-DOC-05 | `TODO(Q-NNN)` の記録が実在する | A    | 検査スクリプト                   | 0 件       |
| CHK-DOC-06 | 起票を実装後に残さない         | A    | 検査スクリプト（取り込む前のみ） | 0 件       |
| CHK-DOC-07 | 太字記法と区切り線を使わない   | A    | 検査スクリプト                   | 0 件       |
| CHK-DOC-08 | 版を分けたファイルを作らない   | A    | 検査スクリプト                   | 0 件       |

CHK-DOC-04 と CHK-DOC-07 は、規約そのものと雛形を書いた文が引っかかる。`documentation-rules.md`・`coding-standards.md`・この文書・`changes/template.md` は対象から外す。

CHK-DOC-01 から CHK-DOC-03 と CHK-DOC-09 は、業務知識の文書に対する検査であり、業務知識を持たないこのリポジトリでは使わない。番号はバックエンドと揃えるため空けている。
