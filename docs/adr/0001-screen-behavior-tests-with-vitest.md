# ADR-FE-0001 画面の振る舞いを Vitest と React Testing Library で確かめる

## ステータス

承認済み (2026-09-28)

## 背景

エージェントを使った開発の手順（`change-flow`）をバックエンドに揃えるにあたり、失敗するテストを先に書いて依頼者の承認を取る段が要る。フロントエンドにはテストの仕組みがなかった。

何をテストで確かめるかも決める必要があった。候補は (a) 画面の振る舞いだけを確かめる・(b) API との通信まで確かめる・(c) 見た目まで確かめる（スナップショットや画像の比較）である。

テストの実行基盤の候補は (1) Vitest・(2) Jest・(3) Playwright などのブラウザを動かす E2E である。

## 決定

Vitest と React Testing Library を使い、画面の単位で、操作と状態に応じた振る舞いだけを確かめる。

## 理由

- 確かめたいのは「何かをしたら何が出るか」「状態によってどの画面が出るか」である。これは利用者の言葉でそのまま書けるため、関門2で開発経験の浅い依頼者に業務の言葉で提示できる
- API との通信（b）は確かめない。データの取得と送信はフックの差し替えで固定する。通信の正しさはバックエンドのテストが受け持っており、フロントエンドで重ねると API の変更のたびに両方が壊れる
- 見た目（c）は確かめない。部品の並びや余白はデザインの担当であり、テストにすると表示の調整のたびに落ちて、振る舞いの退行と区別がつかなくなる
- Jest（2）は不採用とした。TypeScript と ESM を動かすための変換の設定が要る。Vitest は設定が少なく、`@/` の別名も同じ書き方で解決できる
- E2E（3）は不採用とした。バックエンドを起動しないと動かず、手順の中で何度も回すには重い。画面の振る舞いを確かめる目的には過剰である

## 影響

- テストの書き方の規約を `docs/architecture/coding-standards.md` の「テスト」に置いた
- テストは Container を描画し、データのフックを `vi.mock` で差し替える。フックの分け方が Container と Presentational の分離に依存するため、この分離を崩すとテストも書きにくくなる
- 画面をまたぐ遷移や、実際の API と組み合わせた確認は対象外である。必要になったら E2E の導入を別に判断する
