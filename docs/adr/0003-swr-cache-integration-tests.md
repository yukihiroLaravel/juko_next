# ADR-FE-0003 SWR のキャッシュに関わる振る舞いは HTTP の層を差し替えて確かめる

## ステータス

承認済み (2026-10-18)

## 背景

ADR-FE-0001 は、データのフックを差し替えて画面の振る舞いだけを確かめ、API との通信は確かめないと決めた。

受講生側のお知らせ詳細（JKA-1810）で、フックを差し替えたテストでは見つからない不具合が出た。詳細の取得に失敗したあと、モーダルを閉じて開き直しても取り直さずに失敗を表示し続けるものである。SWR は取得の失敗をキャッシュに残し、残っている間は取り直さない。フックを差し替えると SWR そのものが動かないため、この種の振る舞いはテストに現れない。

候補は (a) フックの差し替えだけで確かめ、キャッシュの振る舞いは画面で確かめる・(b) SWR のキャッシュに関わる振る舞いに限り、HTTP の層を差し替えて本物の SWR を動かす・(c) E2E を導入する、である。

## 決定

SWR のキャッシュに関わる振る舞いに限り、axios のインスタンスを差し替え、本物の SWR を動かすテストを置く。それ以外は ADR-FE-0001 のとおりフックを差し替える。

## 理由

- 開き直したときに取り直すか・取得できた詳細を残すか・送信の成功後に一覧を取り直すかは、利用者に見える振る舞いである。フックを差し替えると SWR が動かず、確かめられない
- 対象を SWR のキャッシュに限るため、API の変更のたびに両方が壊れるという ADR-FE-0001 の懸念は小さく保てる
- (a) は不採用とした。今回の不具合はレビューで見つかるまで残っており、画面での確認だけに頼ると退行を防げない
- (c) は不採用とした。ADR-FE-0001 と同じく、バックエンドを起動しないと動かず、手順の中で回すには重い

## 影響

- 置き場と書き方は `docs/architecture/coding-standards.md` の「テスト」に書いた
- 送る値の形や API のパスは、このテストでも確かめない。確かめるのは取得と再取得の有無と、画面に出る結果である
- フック単体のテストは書かない。フックの振る舞いは Container の描画を通して確かめる
