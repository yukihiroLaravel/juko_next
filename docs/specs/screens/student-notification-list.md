# 受講生側 お知らせ一覧

## 目的と利用者

受講生が、受講している講座のお知らせを一覧し、選んだお知らせの本文を読むための画面である。

## 関連コンテキスト

`shared`（一覧に出すお知らせの範囲は、バックエンドの AC-NOTIF-014 に従う）

## パス

`/notifications`

## 表示項目

お知らせは1件を表の1行で表示する。

| 項目     | 表示                                           |
| -------- | ---------------------------------------------- |
| タイトル | そのまま表示する                               |
| 講座名   | そのまま表示する                               |
| 開始日付 | 掲示を始める日時を「2026/10/07」の形で表示する |

行を押すと、お知らせの詳細をモーダルで表示する。

| 項目     | 表示                                 |
| -------- | ------------------------------------ |
| 講座名   | 「お知らせ：講座名」                 |
| 受講期限 | 期限日を「2026/12/31」の形で表示する |
| タイトル | そのまま表示する                     |
| 本文     | 改行を保って表示する                 |

## 受け入れ基準

1. `AC-SNLIST-001` 初期表示のとき、システムはお知らせを開始日付の新しい順に、1ページ5件ずつ表示しなければならない。
2. `AC-SNLIST-002` タイトル・講座名・開始日付の並び替えのボタンが押されたとき、システムはその列の昇順で1ページ目から表示しなければならない。講座名は講座の登録順に並べ、講座名の文字の順にはしない。
3. `AC-SNLIST-003` 並び替えている列のボタンがもう一度押されたとき、システムは昇順と降順を入れ替えて1ページ目から表示しなければならない。
4. `AC-SNLIST-004` 並び替えとページの分割はサーバー側で処理しなければならない（取得したページの中だけで並べ替えない）。
5. `AC-SNLIST-005` システムは、並び替えている列にだけ昇順か降順かの向きを示し、ほかの列には向きのない印を示さなければならない。
6. `AC-SNLIST-006` ページ番号が押されたとき、システムはそのページのお知らせを表示しなければならない。
7. `AC-SNLIST-007` お知らせが減るなどして表示中のページがなくなったとき、システムは最後のページを表示し直さなければならない。
8. `AC-SNLIST-008` お知らせの行が押されたとき、またはキーボードで行を選んで Enter か Space が押されたとき、システムはそのお知らせの詳細を取得し、モーダルで表示しなければならない。一覧を取り直した結果その行がなくなっても、開いたモーダルを維持しなければならない。
9. `AC-SNLIST-009` 詳細のモーダルが閉じられたとき、システムは開いたときのお知らせの行にフォーカスを戻さなければならない。
10. `AC-SNLIST-010` 詳細を表示するとき、システムは受講期限がある場合だけ表示し、期限がない場合はラベルも値も表示してはならない（AC-NOTIF-022）。
11. `AC-SNLIST-011` 詳細の読み込み中、システムはモーダル内に「お知らせを読み込んでいます。」を表示し、閉じる操作を使えるようにしなければならない。
12. `AC-SNLIST-012` 詳細の取得に失敗したとき、システムはモーダル内に「お知らせの取得に失敗しました。」と再試行の操作を表示しなければならない。取得に失敗したお知らせを閉じて開き直したときは、詳細を取り直さなければならない。
13. `AC-SNLIST-013` 一度きりのお知らせを開いたとき、システムは確認済みの記録を送らなければならない。常時表示のお知らせでは送ってはならない（AC-NOTIF-023）。
14. `AC-SNLIST-014` 確認済みの記録の送信に失敗しても、システムは詳細の表示を続け、画面上に失敗を表示してはならない。
15. `AC-SNLIST-015` 一覧の画面を開いている間、システムは同じお知らせの確認済みの記録を1回だけ送らなければならない。送信中や失敗のあとに開き直しても、並び替えやページの移動のあとでも送らない。画面を離れて戻ったときは、もう一度送る（AC-NOTIF-026）。
16. `AC-SNLIST-016` 確認済みの記録の送信に成功したとき、システムは一覧を取り直さなければならない。失敗したときは取り直さない。
17. `AC-SNLIST-017` 詳細を取得できたお知らせを閉じて開き直したとき、システムは取り直さずにその詳細を表示しなければならない。

## 状態別の挙動

| 状態             | 表示                                                               |
| ---------------- | ------------------------------------------------------------------ |
| 0件              | 「現在、お知らせはありません。」を出す。表とページ送りは出さない   |
| 読み込み中       | 表の見出しと5件分の行のスケルトンを出す                            |
| エラー           | 「エラーが発生しました」を出す                                     |
| 取り直している間 | ページの切り替えと並び替えでは、取り直す前の一覧を出したままにする |

## 画面遷移

受講生のヘッダーのメニューからの導線はまだない（JKA-1859）。

## 対象外

- 一覧への受講期限の列の追加
- 既読・未読の表示と、講師の呼び名・既読状態での並び替え
- ページの再読み込みや画面への再訪をまたいで、確認済みの記録を重ねて送らないこと
